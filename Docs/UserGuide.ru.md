# VideoArchive — руководство пользователя

Это руководство описывает фактическое поведение текущей версии VideoArchive: установку, запуск, консольное и графическое меню, параметры командной строки, все поля конфигурации, правила обработки, результаты, логи и диагностику.

## Содержание

1. Назначение и поддерживаемые файлы
2. Установка и быстрый запуск
3. Консольное, Advanced- и графическое меню
4. Параметры командной строки
5. `config.json`
6. `presets.json`
7. `smartskip.json`
8. `devices.json`
9. Выходные файлы, HDR и валидация
10. Resume, журналы и прогресс
11. Безопасное использование и типичные ситуации

## 1. Назначение программы

VideoArchive создаёт архивные копии видео и старается уменьшить размер файлов без изменения разрешения и частоты кадров. Перед сохранением результата программа:

1. находит поддерживаемые видео;
2. анализирует контейнер, кодеки, HDR, разрешение, FPS, звук и rotation metadata через MediaInfo;
3. определяет дату съёмки через ExifTool, имя файла или разрешённый filesystem fallback;
4. применяет Smart Skip;
5. кодирует видео либо выполняет metadata-only операцию;
6. восстанавливает metadata и Windows timestamps;
7. проверяет результат;
8. удаляет результат, если обязательная проверка не пройдена.

Исходные файлы не изменяются. Результаты создаются в отдельных каталогах.

## 2. Поддерживаемые входные файлы

Текущий `config.json` разрешает:

```text
.mp4 .mov .mkv .m4v .mts .m2ts .avi .wmv .webm
```

Для каталога поиск выполняется рекурсивно, а относительная структура подпапок сохраняется. Для одиночного файла расширение также должно присутствовать в `extensions`.

Список расширений управляет только поиском файлов. Реальная возможность декодирования зависит от выбранного энкодера и его FFmpeg/libav-компонентов.

## 3. Установка и внешние программы

Обязательны:

```text
MediaInfo/MediaInfo.exe
ExifTool/exiftool.exe
```

Также должен присутствовать хотя бы один энкодер:

```text
NVEncC/NVEncC64.exe       NVIDIA
QSVEncC/QSVEncC64.exe     Intel Quick Sync
VCEEncC/VCEEncC64.exe     AMD AMF
FFmpeg/ffmpeg.exe          software HEVC/libx265
```

Пути задаются в `config.json`. Относительные пути считаются относительно корня проекта.

## 4. Быстрый запуск

### Консольное меню

Запустите:

```text
VideoArchive.cmd
```

Скрипт предпочитает `pwsh`, если он установлен, иначе использует Windows PowerShell.

Главное меню:

```text
1. Archive
2. Balanced
3. Fast
4. Storage
5. Advanced
```

Enter выбирает пресет, указанный в `defaultPreset`.

### Графический интерфейс

Запустите:

```text
VideoArchive.GUI.cmd
```

GUI требует Windows PowerShell с WPF и запускается в STA-режиме.

### Прямой запуск PowerShell

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video" `
  -Preset Balanced
```

## 5. Обычное консольное меню

Пункты 1–4 выбирают профиль качества. После этого программа запрашивает путь к файлу или каталогу.

Путь можно вводить в кавычках или без них. Поддерживаются локальные диски и UNC-пути. Каталоги обходятся рекурсивно.

## 6. Advanced-меню

Операции Advanced:

```text
1. Video rotation
2. Capture time shift (folder, no re-encoding)
```

Enter на этом экране выбирает `Video rotation`.

### Сдвиг времени съёмки

Выберите `2`, укажите папку, затем сдвиг со знаком: `+03:00:00` прибавляет три часа, `-01:30:00` вычитает полтора часа. Часы могут быть больше 24; нулевой сдвиг не принимается.

Обрабатываются также вложенные папки. Дата определяется по обычным правилам проекта: метаданные, имя файла, затем разрешённый в настройках файловый fallback. При отсутствии даты файл получает ошибку и остаётся без изменений.

FFmpeg перепаковывает все потоки с `-c copy`: видео и звук не перекодируются. MP4/MOV/M4V/MKV сохраняют контейнер; остальные форматы перепаковываются в MKV с добавлением `.mkv` к имени. Несовместимые с контейнером потоки приводят к ошибке, а не к скрытому перекодированию. Для MP4/MOV/M4V метаданные копируются через ExifTool, дата исправляется и проверяется повторным чтением. В MKV дата записывается средствами FFmpeg; перенос всех специфичных тегов исходного контейнера не гарантируется.

Результат сохраняется рядом с исходной папкой в `<папка>_TimeShifted` с сохранением структуры. Исходники и существующие результаты не перезаписываются. Файловые даты результата устанавливаются в исправленное время съёмки. Имена исходных роликов сохраняются. Сдвиг не меняет длительность и синхронизацию дорожек. Нужны FFmpeg и ExifTool по путям из `config.json`.

Запуск без меню (также поддерживается `-DryRun`):

```powershell
.\VideoArchive.ps1 -InputPath 'D:\Video' -TimeShift '-03:00:00'
```

### Выбор поворота

Далее доступны:

```text
1. Metadata rotation — 90° clockwise
2. Metadata rotation — 180° clockwise
3. Metadata rotation — 270° clockwise
4. Physical rotation — 90° clockwise
5. Physical rotation — 180° clockwise
6. Physical rotation — 270° clockwise
```

### Metadata rotation

- не перекодирует видео и звук;
- копирует исходный файл и изменяет display rotation matrix через ExifTool;
- поддерживает только MP4, MOV и M4V;
- сохраняет исходное расширение независимо от `output.container`;
- не использует пресет качества;
- в баннере отображается `Preset: n/a (metadata-only stream copy)`.

Угол является добавочным. Если исходный файл уже содержит поворот 90°, выбор ещё 90° даст итоговые 180°.

### Physical rotation

- физически поворачивает декодированные кадры;
- перекодирует видеопоток;
- после выбора угла предлагает выбрать Archive, Balanced, Fast или Storage;
- звук обрабатывается по обычной секции `audio`;
- после кодирования rotation metadata устанавливается в 0;
- для 90° и 270° валидатор ожидает перестановку ширины и высоты.

После выбора режима программа запрашивает путь к одному видеофайлу и запускает трансформацию.

## 7. Графический интерфейс

### Вкладка Queue

Основные поля:

- `Preset` — профиль качества;
- `Backend` — `auto`, `nvenc`, `qsv`, `amf`, `software`;
- `Codec` — `auto`, `hevc`, `av1`;
- `Force` — принудительная обработка;
- `NoSmartSkip` — отключение Smart Skip;
- `DryRun` — симуляция;
- `Resume` и режим Resume;
- `Advanced — Rotation` — `none`, `metadata`, `physical` и угол `0/90/180/270`.

Добавление заданий:

- `Add Files` — выбрать файлы;
- `Add Folder` — выбрать каталог;
- `Add From Path` — добавить путь из текстового поля;
- также поддерживается drag-and-drop.

Очередь выполняется последовательно. `Stop Current` останавливает текущий дочерний процесс. Кнопки журнала и пути открывают соответствующие объекты в Проводнике.

### Вкладка Presets

Позволяет:

- просматривать параметры пресета;
- клонировать пресет под новым именем;
- редактировать и сохранять поля `presets.json`;
- перечитывать пресеты с диска.

### Вкладка History

Показывает файлы журналов, позволяет обновлять список, читать выбранный журнал и открывать его или каталог журналов.

## 8. Параметры командной строки

| Параметр | Значения | Назначение |
|---|---|---|
| `-InputPath` | файл или каталог | Входной файл либо рекурсивно сканируемый каталог. Если не указан, путь запрашивается интерактивно. |
| `-Preset` | имя из `presets.json` | Профиль качества. Если не указан, открывается главное меню. |
| `-Force` | switch | Обрабатывает файл независимо от Smart Skip и существующего результата; отключает удаление по недостаточной экономии. |
| `-NoSmartSkip` | switch | Полностью отключает Smart Skip для запуска, включая пропуск существующих результатов; удаление по недостаточной экономии также отключается. |
| `-DryRun` | switch | Выполняет анализ и решения, но не создаёт выходной файл. |
| `-Resume` | switch | Продолжает работу по последнему JSONL-журналу. |
| `-ResumeFrom` | путь к JSONL | Использует конкретный JSONL-журнал. Само наличие параметра активирует Resume. TXT и CSV для Resume не предназначены. |
| `-ResumeMode` | `unfinished`, `failed`, `all` | Определяет, какие файлы планировать повторно. По умолчанию `unfinished`. |
| `-EncoderBackend` | `auto`, `nvenc`, `qsv`, `amf`, `software` | Выбор реализации энкодера. По умолчанию `auto`. |
| `-OutputCodec` | `auto`, `hevc`, `av1` | Целевой видеокодек. `auto` использует `encoder.defaultCodec`. |
| `-RotationMode` | `config`, `none`, `metadata`, `physical` | Режим поворота. `config` читает секцию `advanced`. |
| `-RotationDegrees` | `config`, `0`, `90`, `180`, `270` | Добавочный угол по часовой стрелке. |

Приоритет явных параметров CLI выше соответствующих значений конфигурации.

### Примеры

Обычная обработка каталога:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video" -Preset Balanced
```

Проверка решений без записи:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video" -Preset Archive -DryRun
```

Принудительный NVENC HEVC:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video" -Preset Archive -EncoderBackend nvenc -OutputCodec hevc -Force
```

Metadata-only поворот:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video\clip.mp4" -Preset Balanced `
  -RotationMode metadata -RotationDegrees 90
```

Указанный здесь `Balanced` нужен только для загрузки общей конфигурации и не влияет на потоки metadata-only операции.

Физический поворот:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video\clip.mts" -Preset Archive `
  -RotationMode physical -RotationDegrees 270
```

Повтор только ошибок конкретного запуска:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\VideoArchive.ps1 `
  -InputPath "D:\Video" -Preset Balanced `
  -ResumeFrom ".\Logs\VideoArchive_20260822_120000.jsonl" `
  -ResumeMode failed
```

## 9. `config.json`

Файл должен оставаться корректным JSON: комментарии и завершающие запятые не поддерживаются. Перед ручным редактированием рекомендуется сделать копию. Консольный запуск читает конфигурацию заново каждый раз; GUI загружает основную конфигурацию при старте, поэтому после её изменения GUI лучше перезапустить. Значения `true`/`false` записываются без кавычек.

### Корневые поля

| Поле | Текущее значение | Назначение |
|---|---:|---|
| `appName` | `VideoArchive` | Имя в баннере. |
| `defaultPreset` | `Balanced` | Пресет по Enter и технический пресет metadata-only режима. |
| `extensions` | массив | Расширения, которые Scanner считает видео. Регистр не важен. |

### `output`

| Поле | Значения | Назначение |
|---|---|---|
| `hdrSuffix` | строка | Суффикс каталога HDR-результатов, сейчас `_HDR_Encoded`. |
| `sdrSuffix` | строка | Суффикс каталога SDR-результатов, сейчас `_SDR_Encoded`. |
| `container` | `mp4`, `mkv`, `source` | Политика выходного контейнера. |
| `logsFolder` | путь | Каталог TXT/CSV/JSONL-журналов относительно проекта или абсолютный путь. |
| `tempFolder` | путь | Зарезервировано для будущего общего temp-каталога. Сейчас временный encode-файл создаётся рядом с итоговым файлом с именем `_va_tmp_<RunId>`. |

Политика контейнера:

- `mp4` — все обычные encode-результаты получают `.mp4`;
- `mkv` — все обычные encode-результаты получают `.mkv` и обязательный `.metadata.json` sidecar;
- `source` — сохраняет `.mp4`, `.mov`, `.m4v`, `.mkv`; остальные контейнеры переходят в MKV;
- metadata-only rotation всегда сохраняет исходное MP4/MOV/M4V расширение.

MP4 обеспечивает широкую совместимость, но не поддерживает некоторые потоки, например PGS-субтитры. Если такие потоки важны, используйте MKV и проверяйте результат.

### `metadata`

| Поле | Значения | Назначение |
|---|---|---|
| `copyAllMetadata` | boolean | Поле совместимости. Текущий pipeline всегда запускает копирование metadata; переключатель пока не отключает его. |
| `preserveWindowsTimestamps` | boolean | Восстанавливает CreationTime, LastWriteTime и LastAccessTime и включает их в валидацию. |
| `fileTimestampMode` | `captureDate`, `preserve` | `captureDate` устанавливает все три времени по дате съёмки, если она известна; `preserve` копирует отдельные filesystem timestamps исходника. |

### `audio`

| Поле | Значения | Назначение |
|---|---|---|
| `mode` | `copy`, `aac` | Политика аудиодорожек. В поставляемом конфиге используется `aac`. |
| `aacBitrateKbps` | положительное число или `source` | Битрейт только для дорожек, перекодируемых в AAC. |

Правила:

- `copy` копирует все звуковые дорожки;
- `aac` сохраняет уже существующие AAC без перекодирования и конвертирует только не-AAC дорожки;
- `source` использует заявленный битрейт каждой исходной дорожки;
- если MediaInfo не сообщает битрейт, используется fallback 256 kbps;
- небольшой сдвиг отображаемого AAC-битрейта после кодирования нормален из-за кодера и контейнера.

### `advanced`

| Поле | Значения | Назначение |
|---|---|---|
| `rotationMode` | `none`, `metadata`, `physical` | Поворот по умолчанию для CLI с `-RotationMode config`. |
| `rotationDegrees` | `0`, `90`, `180`, `270` | Добавочный угол по часовой стрелке. При 0 режим нормализуется в `none`. |

Оставляйте `none/0` для обычных архивных запусков. Ненулевое значение применяется ко всем файлам запуска.

### `dates`

| Поле | Значения | Назначение |
|---|---|---|
| `timezoneMode` | `sourceOrZone`, `sourceOnly`, `none` | Правило определения offset для даты без явного часового пояса. |
| `defaultTimezone` | идентификатор зоны | Зона с историческими правилами, сейчас `Europe/Moscow`. На Windows также поддерживается соответствие `Russian Standard Time`. |
| `unknownTimezonePolicy` | `keepLocal` | Единственная текущая политика: сохранить локальные часы без выдуманного offset. |
| `preferFileNameOverFileSystemDates` | boolean | Поле совместимости. Реальный порядок всегда ставит имя выше filesystem fallback; значение `false` сейчас не меняет порядок. |
| `fileDateFallbackMode` | `disabled`, `creationTime`, `lastWriteTime` | Разрешает или запрещает использование Windows timestamp как последнего источника даты. |
| `setAllCommonDateTags` | boolean | При найденной дате записывает общий набор QuickTime/Keys/XMP тегов. Для metadata-источника `false` пропускает дополнительную нормализацию тегов. |
| `strictDateMode` | boolean | Если дата не найдена, файл не принимается к обычной обработке. При `false` работа продолжается с предупреждением. |

Фактический приоритет даты:

```text
metadata → filename → разрешённый filesystem fallback → дата отсутствует
```

Правила часового пояса:

- явный offset камеры всегда имеет приоритет;
- `sourceOrZone` применяет исторический offset `defaultTimezone` к локальным часам без зоны;
- `sourceOnly` не добавляет configured zone, но сохраняет явный offset источника;
- `none` не добавляет offset;
- при неизвестном offset сохраняются локальные часы и пишется предупреждение;
- QuickTime integer dates в MP4 записываются как UTC;
- `Keys:CreationDate` и XMP сохраняют локальное время вместе с offset.

Именно поэтому, например, московское `2014-02-16 16:36:29+04:00` отображается MediaInfo как `2014-02-16 12:36:29 UTC`.

Поддерживаются распространённые имена Android, Pixel, Imou, Insta360, WhatsApp, Telegram, Signal, DJI, GoPro и компактные/ISO-подобные даты. Metadata всё равно имеет более высокий приоритет.

### `encoder`

| Поле | Значения | Назначение |
|---|---|---|
| `defaultBackend` | `auto`, `nvenc`, `qsv`, `amf`, `software` | Начальное значение Backend в GUI. В прямом CLI значение `-EncoderBackend auto` выбирает backend по `autoBackendOrder`. |
| `defaultCodec` | `hevc`, `av1` | Кодек для CLI `-OutputCodec auto`. |
| `allowHdrAv1` | boolean | Разрешает AV1 для HDR. При `false` запрос HDR AV1 автоматически переходит на HEVC. |
| `detectHardwareOnStartup` | boolean | Разрешает определение видеокарт через CIM. |
| `alwaysPromptEncoderChoiceWithoutRtx` | boolean | При `auto/auto` предлагает выбор, если NVIDIA RTX не обнаружена. |
| `alwaysPromptEncoderChoice` | boolean | Всегда предлагает выбор backend/codec при `auto/auto`. |
| `autoBackendOrder` | массив | Порядок поиска доступного backend для нужного кодека. |
| `preferredGpu` | целое число | Номер устройства для Rigaya-энкодеров, если поддерживается `--device`. |

Совместимость кодеков:

| Backend | HEVC | AV1 |
|---|---:|---:|
| `nvenc` | да | да |
| `qsv` | да | да |
| `amf` | да | нет |
| `software` | да | нет |

`software` использует FFmpeg + libx265. Для него значения `nvPreset` приблизительно переводятся в x265 preset.

### `tools`

| Поле | Назначение |
|---|---|
| `nvenc` | Путь к NVEncC64.exe. |
| `qsvenc` | Необязательный путь к QSVEncC64.exe. |
| `amfenc` | Необязательный путь к VCEEncC64.exe. |
| `ffmpeg` | Необязательный путь к ffmpeg.exe для software backend. |
| `exiftool` | Обязательный путь к exiftool.exe. |
| `mediainfo` | Обязательный путь к MediaInfo.exe. |

## 10. `presets.json`

Каждое корневое свойство является именем пресета.

| Поле | Назначение |
|---|---|
| `description` | Описание в меню и GUI. |
| `qvbrHdr` | Целевой уровень качества HDR. Меньше — выше качество и обычно больше файл. |
| `qvbrSdr` | Целевой уровень качества SDR. |
| `nvPreset` | Баланс скорости/качества Rigaya, например `p4`, `p5`, `p7`. |
| `lookahead` | Глубина lookahead в кадрах. |
| `multipass` | `none`, `2pass-quarter`, `2pass-full`; применяется Rigaya для HEVC. |
| `aqStrength` | Сила adaptive quantization. |
| `bFrames` | Количество B-frames. |
| `refFrames` | Количество reference frames. |
| `spatialAQ` | Включает spatial AQ. |
| `temporalAQ` | Включает temporal AQ. |
| `adaptiveI` | Разрешает adaptive I-frame placement. |
| `adaptiveB` | Разрешает adaptive B-frame placement. |
| `strictGop` | Включает strict GOP. |

Встроенные профили:

- `Archive` — максимальное качество, медленнее и обычно крупнее;
- `Balanced` — рекомендуемый баланс;
- `Fast` — более быстрое кодирование;
- `Storage` — максимальное сжатие среди штатных профилей.

Не все дополнительные switches поддерживаются каждой версией энкодера. VideoArchive проверяет `--help` и добавляет необязательные параметры только при наличии поддержки.

## 11. `smartskip.json`

| Поле | Назначение |
|---|---|
| `enabled` | Главный переключатель Smart Skip. |
| `skipAv1` | Пропускать входные AV1-файлы. |
| `skipSmallFilesMb` | Порог размера малого файла в MiB. |
| `encodeSmallModernFiles` | Кодировать современные контейнеры меньше порога. В текущем файле `true`. |
| `legacySourceExtensions` | Контейнеры, которые всегда требуют архивного транскода независимо от размера. |
| `skipHevcBelowMbps1080p` | Порог HEVC для видео ниже 4K. |
| `skipHevcBelowMbps4k` | Порог HEVC при максимальном измерении от 2160 до 7679. |
| `skipHevcBelowMbps8k` | Порог HEVC при максимальном измерении от 7680. |
| `skipIfOutputExists` | Пропускать существующий результат. Для MKV также требуется sidecar. |
| `deleteOutputIfSavingsBelowPercent` | Удалять валидный encode-результат, если экономия меньше порога. |

В текущей конфигурации legacy-контейнеры:

```text
.mts .m2ts .avi .wmv .webm
```

Они кодируются даже при размере меньше 50 MiB. Результаты legacy, явно разрешённых малых современных файлов и поворотов защищены от удаления по низкой экономии.

Упрощённый порядок решений:

1. `Force` или `NoSmartSkip` — кодировать;
2. существующий результат — пропустить, если политика разрешает;
3. legacy container — кодировать;
4. запрошенный поворот — выполнить;
5. AV1 — пропустить, если включено;
6. малый современный файл — применить `encodeSmallModernFiles`;
7. HEVC — сравнить битрейт с порогом разрешения;
8. остальные кодеки — кодировать в целевой архивный кодек.

Защищённые HDR-типы (`HDR Vivid`, `Dolby Vision`, `HDR10+`) не пропускаются только из-за низкого HEVC-битрейта.

## 12. `devices.json`

Файл содержит описательные профили устройств (`Default`, `Honor`, `iPhone`, `GoPro`, `DJI`). В текущей версии он загружается в конфигурацию, но не участвует автоматически в выборе пресета, кодека или HDR-политики. Это задел для будущих device-specific правил.

## 13. Выходные каталоги и файлы

Для входного каталога:

```text
D:\Video
```

создаются:

```text
D:\Video_HDR_Encoded
D:\Video_SDR_Encoded
```

Для одиночного файла каталоги создаются рядом с его родительским каталогом. Относительные подпапки сохраняются.

Временный файл имеет вид:

```text
name_va_tmp_yyyyMMdd_HHmmss.mp4
```

Он создаётся в итоговом каталоге и после успеха переименовывается в финальное имя.

Для MKV создаётся:

```text
name.mkv
name.metadata.json
```

Sidecar содержит дату съёмки, offset/UTC, источник даты, GPS, исходный путь и fingerprint. MKV без обязательного sidecar не считается завершённым для Smart Skip и Resume.

## 14. HDR, кодек и валидация

MediaInfo классифицирует SDR, HLG, PQ, HDR10, HDR10+, HDR Vivid, Dolby Vision и Unknown HDR.

Обычная политика:

- SDR HEVC — Main, 8-bit;
- HDR HEVC — Main10, 10-bit;
- разрешение и FPS не меняются;
- HDR transfer/primaries/matrix стараются сохраняться;
- HDR Vivid/Dolby Vision dynamic metadata могут не пережить транскод, но базовый HDR должен остаться совместимым.

Перед принятием результата проверяются:

- существование и ненулевой размер;
- кодек;
- разрешение с учётом физического поворота;
- rotation metadata;
- FPS;
- bit depth;
- HDR и цветовые характеристики;
- число, кодек и каналы аудиодорожек;
- даты, GPS и Windows timestamps;
- MKV sidecar.

При ошибке валидации итоговый файл и sidecar удаляются, а в журнал записывается `Failed`.

## 15. Resume

Resume использует JSONL-журнал предыдущего запуска.

Режимы:

- `unfinished` — пропустить подтверждённые завершённые файлы и продолжить незавершённые;
- `failed` — повторить только файлы, последняя запись которых имеет `Action=Failed`;
- `all` — запланировать все найденные входные файлы.

Завершённая запись повторно обрабатывается, если:

- выходной файл исчез;
- для MKV отсутствует sidecar;
- изменился source fingerprint;
- текущий пресет отличается от записанного в журнале.

`-Resume` без `-ResumeFrom` выбирает последний подходящий JSONL в каталоге журналов.

## 16. Журналы

Каждый запуск создаёт базовое имя:

```text
Logs\VideoArchive_yyyyMMdd_HHmmss
```

Форматы:

- `.txt` — краткий человекочитаемый журнал;
- `.csv` — таблица по файлам;
- `.jsonl` — полные машинные записи и источник Resume.

JSONL содержит пути, действие, причину, размеры, экономию, HDR, разрешение, даты, предупреждения/ошибки валидации, backend и кодек.

## 17. Строка прогресса

Пример:

```text
Progress: [#####-------------------] 1/5 (20%) | ETA 08:43 | Avg/File 02:10 | E:1 S:0 F:0 D:0
```

Счётчики:

- `E` — успешно Encoded и провалидировано;
- `S` — Skipped или отброшено политикой;
- `F` — Failed;
- `D` — обработано в DryRun;
- `R` — пропущено планом Resume, показывается при ненулевом значении.

Счётчик `E` увеличивается только после кодирования, metadata, перемещения и полной валидации, поэтому во время первого файла все значения равны нулю.

## 18. Безопасное использование

Перед большой обработкой рекомендуется:

1. проверить `output.container`, `audio.mode`, `dates.defaultTimezone` и Smart Skip;
2. выполнить `-DryRun`;
3. обработать несколько типичных файлов;
4. проверить видео, звук, HDR, даты и rotation в MediaInfo;
5. только после этого запускать весь архив;
6. не удалять исходники автоматически — VideoArchive этого не делает.

Для даты без offset configured zone является предположением. Если камера снимала в другом часовом поясе, измените `dates.defaultTimezone` перед обработкой соответствующей группы файлов.

## 19. Типичные ситуации

### Выходной файл пропущен

Проверьте причину в строке `Skip (...)` и `smartskip.json`. Частые причины: существующий результат, малый современный файл, AV1 или HEVC ниже порога.

### Нужна гарантированная повторная обработка

Используйте `-Force`. Он также предотвращает удаление результата из-за низкой экономии.

### Нужен только поворот без потери качества

Используйте metadata rotation для MP4/MOV/M4V. Не все проигрыватели одинаково учитывают display matrix; для гарантированного отображения используйте physical rotation.

### После физического поворота поменялись Width и Height

Для 90°/270° это ожидаемо: `1920×1080` становится `1080×1920`.

### MediaInfo показывает UTC-время, отличное от времени камеры

Сравните `Keys:CreationDate` с offset. Например, `16:36:29+04:00` и `12:36:29 UTC` обозначают один момент.

### AC-3 стал AAC

Это соответствует `audio.mode = "aac"`. Чтобы всегда копировать звук, установите `audio.mode = "copy"`.

### AAC-битрейт немного отличается

`aacBitrateKbps = "source"` передаёт исходное целевое значение кодеру, но MediaInfo может показать немного другое номинальное/среднее значение.

### MKV не содержит встроенную дату съёмки

Проверьте соседний `.metadata.json`. Для MKV это обязательный источник архивной даты в текущей архитектуре.
